# EchoTalking 产品定位与体验优化

## 1. 文档状态

- 状态：产品与体验设计提案
- 产品暂定名：EchoTalking
- 对标产品：Discord
- 目标：补齐成熟聊天工具的基础体验，并建立“人与多个 Agent 在同一空间协作”的差异化
- 本文不意味着直接复制 Discord 的服务器、语音或商业体系

## 2. 产品定位

EchoTalking 是一个以聊天为交互界面、以 Agent 协作为核心能力的多人工作空间。

一句话描述：

> 人与智能体共同参与的多人聊天空间。

与普通 AI Chat 的区别：

- 对话属于房间和团队，不只是单用户与单模型的临时会话。
- 一个房间可包含多个具有不同模型、Skill、工具与权限的 Agent。
- Agent 可以被显式邀请，也可以由 Supervisor 按能力分流。
- Agent 的执行可暂停、审批、恢复、审计，而不是黑盒请求。
- 输出可以沉淀为 Thread、结论、任务、Artifact 或可复用工作流。

与 Discord 的区别：

- Discord 优先解决社群沟通、语音和成员关系。
- EchoTalking 优先解决人类与专业 Agent 围绕上下文共同完成任务。
- EchoTalking 不追求复制 Discord 全部社群功能，而是借鉴其空间层级、聊天效率、在线感和视觉成熟度。

## 3. 目标用户

### 3.1 小型协作团队

在一个房间中讨论需求、调用研究/编程/图片 Agent，并保留决策和执行结果。

### 3.2 AI 重度用户

不希望在多个独立聊天产品之间切换，需要多个模型和专业 Agent 共享同一上下文。

### 3.3 Agent 开发与运营人员

需要配置模型、角色、Skill、MCP、权限、审批和运行策略，并观察执行过程。

## 4. 产品原则

1. 聊天优先：高频发送、回复、搜索和未读处理必须自然快速。
2. Agent 可理解：用户看到参与者、阶段、风险和结果，而不是 Runtime 内部术语。
3. 上下文不污染：长任务、工具过程和多 Agent 协作优先进入 Thread 或详情面板。
4. 权限可解释：高风险工具、Artifact 和 Agent 管理权限必须清楚呈现。
5. 结果可沉淀：重要消息可以转为结论、任务或文档，不被消息流淹没。
6. 渐进复杂：普通聊天保持轻量，高级运行信息按需展开。

## 5. 当前产品差距

当前已经具备：注册登录、房间、成员、结构化 `@`、Agent、Supervisor、文字/图片模型、运行状态、审批和管理台。

相对成熟聊天工具，主要差距是：

- 空间层级主要停留在房间，缺少频道分组、收藏和最近访问。
- 消息缺少引用回复、Thread、Reaction、搜索、置顶和完整附件体验。
- 未读、通知、输入中和在线状态不足，聊天室的实时“在线感”偏弱。
- Agent 执行状态偏工程化，普通用户不容易判断正在做什么、是否需要操作。
- 长 Agent 输出和工具过程容易挤占主消息流。
- 桌面三栏信息架构、移动端抽屉和消息密度仍可系统优化。

## 6. 信息架构

推荐桌面结构：

```text
左栏：空间、频道、未读与收藏
中栏：消息流、Thread 入口、聊天输入
右栏：成员 / Thread / Agent 执行详情（上下文切换）
```

移动端：

```text
频道列表 -> 左侧抽屉
消息流   -> 主页面
成员/Thread/运行详情 -> 右侧抽屉或独立页面
输入框   -> 底部安全区
```

右栏不应永久同时展示所有信息。用户点击成员、Thread 或 Agent 运行时切换上下文，减少主界面拥挤。

## 7. 功能优化方向

### 7.1 回复与 Thread

- 支持引用回复和跳转原消息。
- 支持从消息创建 Thread。
- 展示 Thread 回复数、最后回复者和未读数。
- Thread 内可独立 `@Agent`。
- Agent 长任务默认或可选在 Thread 中执行。

Thread 是隔离子话题、Agent 过程和长结果的核心能力，应作为最高优先级。

### 7.2 消息能力

- 编辑、软删除和审计。
- Emoji Reaction。
- 代码块语法高亮与复制。
- 文件上传、进度、失败和受控下载。
- 图片画廊和全屏预览。
- 链接预览。
- 置顶和消息收藏。
- 草稿保存。
- 未读分割线和“跳到最新消息”。

### 7.3 搜索和知识沉淀

- 房间全文搜索。
- 按发送者、Agent、日期、附件和消息类型筛选。
- 将消息标记为结论或决策。
- 从 Thread 生成摘要。
- 将消息/Thread 转为任务或文档。
- Artifact 元数据可搜索，正文权限沿用房间权限。

### 7.4 在线状态与即时反馈

- 用户在线、离开、忙碌状态。
- “某某正在输入”。
- 消息发送中、已送达、失败和重试状态。
- Agent 排队、读取上下文、调用工具、等待审批、生成结果等阶段。
- 新消息和未读提示。
- 可选桌面通知。

### 7.5 通知中心

- `@我`、Thread 回复、审批请求、Agent 完成和运行失败。
- 按类型筛选、一键已读、跳转到来源。
- 房间和通知类型级别的偏好设置。
- 通知不包含未经授权的消息正文或工具参数。

### 7.6 多 Agent 协作

- Agent 名称旁显示统一 Bot/Agent 标识和能力入口。
- 一条消息显式邀请多个 Agent。
- 展示 Supervisor 选择 Agent 的简短原因。
- Agent 间任务交接和汇总角色。
- 用户可中止、重试或继续单个 Agent 步骤。
- 多个 Agent 结果可比较、选择和汇总。
- 协作流程可保存为可复用模板。

普通用户界面避免直接暴露 DAG、lease、checkpoint 等内部术语。管理台可以保留工程视图。

### 7.7 权限与治理

- 频道级查看、发言和邀请权限。
- 添加 Agent、调用高风险工具、审批和查看 Artifact 的独立权限。
- Agent 费用/Token 限额。
- 邀请链接有效期、使用次数和撤销。
- 管理操作和消息变更保留审计。

## 8. 视觉优化方向

### 8.1 消息流

- 默认消息不使用独立大卡片。
- 同一发送者的连续消息分组，减少重复头像和昵称。
- 消息操作在 hover/focus 时显示，移动端通过长按或菜单触发。
- 昵称、时间和状态使用稳定的一行布局。
- 工具详情和长过程默认折叠。

### 8.2 颜色与语义

避免复制 Discord 的紫蓝主色体系，使用中性界面加少量语义色：

| 用途 | 建议颜色 |
|---|---|
| 当前频道与链接 | 清晰蓝色 |
| 在线、成功 | 青绿 |
| 等待、审批 | 琥珀 |
| 错误、危险 | 珊瑚红 |
| 普通界面 | 灰白/炭黑中性色 |

颜色不能作为状态的唯一表达，必须同时使用图标和文字。

### 8.3 真人与 Agent 区分

- Agent 名称旁使用一致的标识，而不是只靠头像。
- Agent 状态使用紧凑状态行或时间线。
- 工具、审批、结果和错误使用固定语义样式。
- 避免给每条 Agent 消息使用大面积品牌色背景。

### 8.4 输入框

- 自动增高但设置最大高度。
- 回复上下文清晰可关闭。
- 附件、Emoji、`@`、`/` 命令和 Agent 选择入口明确。
- 上传和发送状态不会改变输入栏整体尺寸。
- 移动端适配软键盘和安全区。

### 8.5 可访问性

- 全键盘操作和可见焦点。
- 屏幕阅读器可识别新消息、Reaction、Thread 和 Agent 状态。
- 颜色对比符合 WCAG AA。
- 动画尊重 `prefers-reduced-motion`。
- 图标按钮提供可访问名称和 Tooltip。

## 9. 优先级路线图

### 第一阶段：聊天基础

1. 引用回复和 Thread。
2. Reaction。
3. 搜索。
4. 未读和通知。
5. 输入中与消息发送状态。

### 第二阶段：Agent 差异化

1. Agent 执行状态时间线。
2. 聊天内审批交互。
3. 多 Agent 邀请、交接和汇总。
4. 结果比较。
5. 输出转任务/文档。

### 第三阶段：空间与治理

1. 工作区和频道分组。
2. 频道权限。
3. 私信或小组对话。
4. 在线状态。
5. 通知偏好和费用配额。

## 10. 非目标

当前阶段明确不做：

- 复制 Discord 的语音、视频、直播和游戏 Overlay。
- 直接实现大型公开社区的完整审核体系。
- 暴露 Runtime 内部控制协议给普通用户。
- 为视觉效果牺牲消息密度、加载性能和可访问性。
- 在缺少真实使用数据时一次性引入所有空间层级。

## 11. 成功指标

- 新用户能在 3 分钟内进入房间并完成一次 Agent 对话。
- 用户能明确判断 Agent 当前阶段和是否需要操作。
- Thread 降低长任务对主消息流的干扰。
- 搜索能在可接受时间内定位历史消息、结论和 Artifact。
- 通知点击能准确定位原消息、Thread 或审批。
- 桌面和移动端无主要重叠、溢出和不可操作控件。
- 聊天核心操作键盘可达，语义状态不依赖单一颜色。

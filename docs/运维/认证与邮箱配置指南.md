# Google 登录与邮箱验证码配置教程

本文介绍如何为 Smart Chat 配置以下两项功能：

1. 使用 Google 账号登录。
2. 注册时通过 Gmail SMTP 发送验证码。

这两项功能互相独立：Google 登录负责确认第三方账号身份，Gmail SMTP 负责由项目邮箱发送注册验证码。

## 一、创建 Google OAuth 应用

### 1. 打开 Google Cloud Console

使用自己的 Google 账号进入 Google Cloud Console。

如果还没有项目，点击顶部项目选择器，新建一个项目：

```text
项目名称：Smart Chat
```

如果已经创建并选中了 `Smart Chat` 项目，就不需要点击“免费试用”，也不需要为了 Google 登录购买云服务器。

### 2. 进入 Google Auth Platform

在控制台顶部搜索框中搜索：

```text
Google Auth Platform
```

打开搜索结果中的 **Google Auth Platform**。第一次进入时，点击 **Get started / 开始使用**。

### 3. 填写应用信息

按照页面提示填写：

```text
应用名称：Smart Chat
用户支持邮箱：你的 Gmail
受众：外部（External）
联系邮箱：你的 Gmail
```

说明：

- 选择“外部”后，其他 Google 用户才有机会使用该应用登录。
- 联系邮箱用于接收 Google 关于 OAuth 应用的通知。
- 这些设置不会授权项目读取用户的 Gmail 邮件。

填写完成后，确认相关政策选项并完成创建。

### 4. 创建 OAuth 客户端

进入 Google Auth Platform 左侧的 **Clients / 客户端** 页面，点击 **Create client / 创建客户端**。

填写：

```text
应用类型：Web application（Web 应用）
名称：Smart Chat Web
```

在“已获授权的 JavaScript 来源”中添加：

```text
http://localhost:3000
```

在“已获授权的重定向 URI”中添加：

```text
http://localhost:3000/api/auth/oauth/google/callback
```

回调地址必须完全一致。协议、域名、端口、路径或末尾斜杠不同，Google 都可能提示 `redirect_uri_mismatch`。

### 5. 复制 Client ID 和 Client Secret

创建成功后，Google 会显示：

```text
Client ID
Client Secret
```

打开项目根目录的 `.env`，填写：

```env
GOOGLE_CLIENT_ID="这里填写Google提供的Client ID"
GOOGLE_CLIENT_SECRET="这里填写Google提供的Client Secret"
```

不要把真实值写进 `.env.example`，也不要把 `.env` 上传到 Git。

### 6. 测试用户（本项目通常不用配置）

本项目的 Google 登录只读取用户的基础身份信息，请求的权限只有：

```text
openid email profile
```

Google 对这类基础身份权限有例外规则：即使应用仍处于 **Testing / 测试** 状态，其他 Google 用户通常也可以直接登录，不要求先加入 **Audience / 受众** 页面的测试用户名单。

因此，本项目目前可以跳过“添加测试用户”这一步。你也可以把自己的账号加进去方便管理，但这不是当前登录功能正常工作的必要条件。

只有以后增加 Gmail 邮件、Google Drive、Calendar 等其他 OAuth 权限时，测试状态下才可能必须添加测试用户，并可能需要完成 Google 应用验证。

如果某个用户仍然无法登录，应优先检查 Client ID、回调地址、账号所属组织的 Google Workspace 管理策略和页面显示的具体错误，而不是默认认为没有加入测试名单。

### 7. 确认项目的 Google 配置

本地开发时，相关 `.env` 配置如下：

```env
APP_ORIGIN="http://localhost:3000"
COOKIE_SECURE=""
GOOGLE_CLIENT_ID="你的Google Client ID"
GOOGLE_CLIENT_SECRET="你的Google Client Secret"
OAUTH_STATE_SECRET="一个至少32字符的随机字符串"
```

生成 `OAUTH_STATE_SECRET`：

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

如果浏览器能访问 Google，但项目后端连接 Google 失败，可以使用自己信任的本机代理。例如 Clash Verge 的 HTTP 代理端口是 `7897` 时：

```env
OAUTH_HTTP_PROXY="http://127.0.0.1:7897"
```

不需要代理时保持为空：

```env
OAUTH_HTTP_PROXY=""
```

### 8. 重启并测试 Google 登录

每次修改 `.env` 后，都要停止原来的开发服务器，再重新运行：

```powershell
npm run dev
```

然后访问：

```text
http://localhost:3000/login
```

点击“使用 Google 登录”。成功后应返回 Smart Chat，并建立项目自己的登录会话。

### 9. Google 登录能读取什么

项目只申请以下基础身份权限：

```text
openid email profile
```

- `openid`：确认用户身份。
- `email`：获取用于登录的邮箱地址。
- `profile`：获取昵称、头像等基础资料。

项目没有申请 Gmail 邮件权限，不能读取收件箱、邮件正文、联系人或附件，也不能用用户的 Google 账号代发邮件。

## 二、配置邮箱验证码

### 1. 开发阶段使用终端验证码

项目默认可以使用：

```env
EMAIL_PROVIDER="console"
```

这种模式不会真正发送邮件。用户点击“发送验证码”后，验证码只会显示在运行 `npm run dev` 的终端中。

它适合本地调试，但不能用于需要真实用户收取邮件的环境。

### 2. 为 Gmail 创建应用专用密码

操作步骤：

1. 点击 Chrome 右上角头像，选择 **管理您的 Google 账号**。
2. 进入 **安全性**。
3. 在“您如何登录 Google”中开启 **两步验证**。
4. 开启后，在 Google 账号页面搜索 **应用专用密码**。
5. 创建一个名称为 `Smart Chat` 的应用专用密码。
6. Google 会生成一组 16 位密码，将它用于项目的 `SMTP_PASSWORD`。

注意：

- 应用专用密码不是 Google 账号的登录密码。
- 页面显示的密码可能带有空格，填写到 `.env` 时去掉空格。
- 应用专用密码通常只显示一次，应立即保存到安全位置。
- 如果撤销或重新生成应用专用密码，旧密码会失效，需要同步修改 `.env`。
- 如果账号没有开启两步验证，通常不会显示“应用专用密码”。
- 学校或公司的 Google Workspace 账号可能被管理员禁止使用应用专用密码。

### 3. 在项目中配置 Gmail SMTP

打开项目根目录的 `.env`，填写：

```env
EMAIL_PROVIDER="smtp"
EMAIL_CODE_SECRET="一个至少32字符且与OAUTH_STATE_SECRET不同的随机字符串"
EMAIL_FROM="Smart Chat <你的Gmail地址@gmail.com>"

SMTP_HOST="smtp.gmail.com"
SMTP_PORT="465"
SMTP_SECURE="true"
SMTP_USER="你的Gmail地址@gmail.com"
SMTP_PASSWORD="Google生成的16位应用专用密码"
```

各配置项的含义：

| 配置项 | 填写内容 |
| --- | --- |
| `EMAIL_PROVIDER` | 使用 `smtp` 才会真正发邮件 |
| `EMAIL_CODE_SECRET` | 用于安全计算验证码摘要的项目密钥 |
| `EMAIL_FROM` | 收件人看到的发件人名称和邮箱 |
| `SMTP_HOST` | Gmail 填写 `smtp.gmail.com` |
| `SMTP_PORT` | SSL 连接使用 `465` |
| `SMTP_SECURE` | 使用 SSL 时填写 `true` |
| `SMTP_USER` | 完整 Gmail 地址 |
| `SMTP_PASSWORD` | Google 生成的 16 位应用专用密码 |

`EMAIL_FROM` 中的邮箱应与 `SMTP_USER` 相同，避免 Gmail 拒绝发送或改写发件人。

生成 `EMAIL_CODE_SECRET` 时，再执行一次随机密钥命令：

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

不要直接复制 `OAUTH_STATE_SECRET`。这两个密钥应分别生成、分别保存。

### 4. 重启并测试邮箱验证码

修改 `.env` 后重新启动项目：

```powershell
npm run dev
```

打开注册页面，填写一个可以正常收信的邮箱，然后点击“发送验证码”。

配置正确时，收件箱会收到 Smart Chat 发出的六位验证码。如果没有看到，先检查垃圾邮件或广告邮件目录。

### 5. 常见发送失败原因

#### SMTP 用户名或密码错误

确认：

- `SMTP_USER` 是完整 Gmail 地址。
- `SMTP_PASSWORD` 是应用专用密码，不是 Google 账号登录密码。
- Google 账号已经开启两步验证。
- 应用专用密码没有被撤销，填写时已经去掉空格。

#### 端口或加密配置不匹配

Gmail SSL SMTP 使用：

```env
SMTP_HOST="smtp.gmail.com"
SMTP_PORT="465"
SMTP_SECURE="true"
```

#### 修改配置后仍然没有生效

Next.js 只会在启动时读取 `.env`。修改环境变量后必须停止并重新运行 `npm run dev`。

#### 发件人与登录邮箱不一致

建议保持：

```env
SMTP_USER="your-account@gmail.com"
EMAIL_FROM="Smart Chat <your-account@gmail.com>"
```

#### 网络连接失败

检查防火墙、校园网或公司网络是否限制了 SMTP 连接。可以临时切换其他网络进行排查。

## 三、本地完整配置参考

下面只展示结构，所有占位文字都要替换成自己的真实配置：

```env
APP_ORIGIN="http://localhost:3000"
COOKIE_SECURE=""

GOOGLE_CLIENT_ID="你的Google Client ID"
GOOGLE_CLIENT_SECRET="你的Google Client Secret"
OAUTH_STATE_SECRET="单独生成的随机密钥A"
OAUTH_HTTP_PROXY="http://127.0.0.1:7897"

EMAIL_PROVIDER="smtp"
EMAIL_CODE_SECRET="单独生成的随机密钥B"
EMAIL_FROM="Smart Chat <你的Gmail地址@gmail.com>"
SMTP_HOST="smtp.gmail.com"
SMTP_PORT="465"
SMTP_SECURE="true"
SMTP_USER="你的Gmail地址@gmail.com"
SMTP_PASSWORD="Google生成的16位应用专用密码"
```

如果不需要 OAuth 代理，将 `OAUTH_HTTP_PROXY` 改为空：

```env
OAUTH_HTTP_PROXY=""
```

## 四、生产环境注意事项

项目部署到公网后，应使用正式域名和 HTTPS：

```env
APP_ORIGIN="https://你的正式域名"
COOKIE_SECURE="true"
```

还需要在 Google Cloud 中增加正式回调地址：

```text
https://你的正式域名/api/auth/oauth/google/callback
```

生产环境应重新生成独立的 `OAUTH_STATE_SECRET` 和 `EMAIL_CODE_SECRET`，不要直接使用开发环境的密钥。

生产环境的真实密钥应配置在服务器或部署平台的环境变量中，不要写进公开仓库。

## 五、最终检查清单

- [ ] 本地 Google 回调地址填写正确。
- [ ] `.env` 中已经填写 Google Client ID 和 Client Secret。
- [ ] 测试账号可以完成 Google 登录。
- [ ] Google 账号已经开启两步验证，并生成应用专用密码。
- [ ] `SMTP_PASSWORD` 填写的是应用专用密码，而不是 Google 登录密码。
- [ ] `EMAIL_PROVIDER` 已从 `console` 改为 `smtp`。
- [ ] 两个安全 Secret 已分别生成，且都不少于 32 个字符。
- [ ] 修改 `.env` 后已经重新启动项目。
- [ ] `.env` 和真实密钥没有提交到 Git。

# Agent Runtime 生产运行手册

## 灰度

1. 先应用向后兼容 migration；新表和新列在 legacy 路径下允许为空。
2. 保持 `AGENT_RUNTIME_MODE=legacy`，部署兼容新数据模型的 Web 与 Worker。
3. 用 `AGENT_RUNTIME_CANARY_MODE` 指定候选 Runtime，以 `AGENT_RUNTIME_CANARY_ROOM_IDS`、`AGENT_RUNTIME_CANARY_AGENT_IDS` 或 `AGENT_RUNTIME_CANARY_KINDS` 定向；最后才逐步增加 `AGENT_RUNTIME_CANARY_PERCENT`。
4. 每一档观察 queue/run/turn/tool latency、失败率、lease lost、recovery、approval wait、Token 与 cost。

百分比分桶由 room/agent 的稳定摘要决定，同一主体不会在重启后随机漂移。显式名单优先于百分比。

## 回滚

将 canary 百分比和名单清空并把 `AGENT_RUNTIME_MODE` 设为 `legacy`，只影响新 Run。不得删除 Runtime 表、Event 或 Checkpoint。已有 Run 按原 `runtimeId/runtimeKind/runtimeVersion` 完成；已经产生工具调用的 Run 禁止跨 Runtime 续跑。仅 `PENDING` 或 `FAILED_RETRYABLE` 且 `toolCallCount=0` 的 Run 可重新路由。

## 告警与处置

- 队列有容量时 claim p95 超过 3 秒：检查 Worker 心跳、租约索引和数据库连接池。
- cancel p95 超过 2 秒：检查轮询周期及 AbortSignal 接线。
- RUNNING 超过租约期限：停止对应 Worker，确认 lease generation 后重领，禁止直接改 owner。
- outcome unknown：保持 BLOCKED，人工核查外部副作用；不得自动重放非幂等工具。
- schema drift：隔离 MCP revision，刷新工具 schema 后创建新 Run，不修改历史 Turn digest。

## 演练与容量基线

运行 `npm run runtime:fault-drill` 输出九类演练的期望终态、恢复预算和一致性证据。运行 `npm run runtime:capacity` 检查 20 并发的唯一 claim、claim/cancel p95 以及 delta 写入边界。生产演练需把输出连同日志查询结果归档，并确认不存在无限 RUNNING Run。

# Smart Chat 腾讯云全 Docker 公网部署指南

## 1. 部署拓扑

腾讯云服务器只安装 Git、Docker 和 Docker Compose，所有应用服务均运行在容器中：

```text
公网 80/443
  -> caddy 容器
  -> web 容器 :3000
       -> postgres 容器 :5432

worker 容器
  -> web:3000 内部 API
  -> postgres:5432
```

Compose 服务：

| 服务 | 职责 | 公网暴露 |
|---|---|---|
| `caddy` | HTTPS、证书续期、反向代理 | TCP 80/443、UDP 443 |
| `web` | Next.js 页面和 REST API | 仅 `127.0.0.1:3000` |
| `worker` | 传统 Agent 后台任务 | 不暴露端口 |
| `postgres` | 权威数据库 | 仅 `127.0.0.1:5432` |
| `runtime-worker` | 可选 Self-hosted Runtime | 默认不启动 |

数据使用 Docker 命名卷持久化：PostgreSQL、Artifact、Caddy 证书和配置不会因容器重建而丢失。

## 2. 腾讯云安全组

开放：

| 端口 | 来源 | 用途 |
|---|---|---|
| TCP 22 | 管理员固定 IP | SSH |
| TCP 80 | `0.0.0.0/0` | ACME 验证和 HTTPS 跳转 |
| TCP 443 | `0.0.0.0/0` | HTTPS |
| UDP 443 | `0.0.0.0/0` | HTTP/3，可选 |

不要开放 3000、3011、5432。

## 3. 安装 Docker

Ubuntu 22.04/24.04：

```bash
sudo apt update
sudo apt install -y ca-certificates curl git make
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
```

重新登录 SSH 后验证：

```bash
docker --version
docker compose version
```

不需要在宿主机安装 Node.js、npm、PostgreSQL、Caddy 或 Nginx。

## 4. 准备代码和环境变量

```bash
cd /opt
git clone <仓库地址> smart-chat
cd /opt/smart-chat
cp .env.example .env
chmod 600 .env
```

生成独立密钥：

```bash
openssl rand -hex 32       # POSTGRES_PASSWORD
openssl rand -base64 48    # SESSION_SECRET
openssl rand -hex 32       # AI_CONFIG_ENCRYPTION_KEY
openssl rand -base64 48    # AGENT_WORKER_SECRET
```

编辑 `.env`：

```env
POSTGRES_PASSWORD="数据库十六进制密码"
POSTGRES_PORT="5432"
APP_PORT="3000"
SMART_CHAT_IMAGE_TAG="latest"

SESSION_SECRET="至少32字符的随机值"
AI_CONFIG_ENCRYPTION_KEY="独立的加密密钥"
AGENT_WORKER_SECRET="独立的Worker认证密钥"

COOKIE_SECURE=true
AGENT_RUNTIME_MODE=legacy
AI_PROVIDER_HOST_ALLOWLIST="api.openai.com,generativelanguage.googleapis.com"
ARTIFACT_RETENTION_DAYS=30
```

## 5. 无自有域名时配置 HTTPS

假设公网 IP 为 `43.130.52.92`，使用临时域名：

```env
PUBLIC_HOST="43-130-52-92.sslip.io"
```

验证解析：

```bash
getent hosts 43-130-52-92.sslip.io
```

应解析到 `43.130.52.92`。Caddy 使用 `deploy/Caddyfile`，通过 Docker 网络直接代理 `web:3000`，自动申请和续期 Let's Encrypt 证书。

`sslip.io` 适合临时部署。购买域名后，将 DNS A 记录指向服务器公网 IP，并把 `PUBLIC_HOST` 改成正式域名，然后重新创建 Caddy 容器。

## 6. 首次部署

如果服务器此前使用宿主机 Caddy 或 Nginx，占用 80/443 会导致 Caddy 容器启动失败。切换到全 Docker 方案前先停止并禁用宿主机反向代理：

```bash
sudo systemctl disable --now caddy 2>/dev/null || true
sudo systemctl disable --now nginx 2>/dev/null || true
sudo ss -lntp | grep -E ':(80|443)\b' || true
```

确认 80/443 已无进程监听，再启动 Compose。Caddy 容器会复用 `smart-chat-caddy-data` 卷保存新申请的证书；宿主机 Caddy 的证书目录不会自动迁移，但这不影响重新申请证书。

一条命令完成检查、构建、数据库启动、migration、Web、Worker 和 Caddy 启动：

```bash
make deploy
```

首次构建需要从 Docker Hub 拉取 Node、PostgreSQL 和 Caddy 镜像，并从 npm 下载依赖。

如果需要演示账号和基础 Agent 数据，部署完成后执行一次：

```bash
docker compose run --rm web npm run db:seed
```

Seed 管理员账号为 `admin@example.com`，密码来自 `.env` 的 `SEED_ADMIN_PASSWORD`。生产环境必须配置强密码。

## 7. 分步部署

```bash
docker compose config --quiet
docker compose build web
docker compose up -d postgres
docker compose run --rm web npx prisma migrate deploy
docker compose --profile worker up -d postgres web worker caddy
```

容器内连接关系由 Compose 覆盖：

```text
web -> postgresql://smart_chat:***@postgres:5432/smart_chat
worker -> http://web:3000/api/internal/agent-worker
caddy -> http://web:3000
```

不能在容器配置中使用 `127.0.0.1` 访问其他容器，因为容器内的回环地址只代表当前容器。

## 8. 验证

```bash
make status
make verify
docker compose --profile worker ps
docker compose logs --tail=100 postgres web caddy
docker compose --profile worker logs --tail=100 worker
curl -I http://127.0.0.1:3000
```

使用 `.env` 中的实际域名验证公网 HTTPS，例如：

```bash
curl -IL https://43-130-52-92.sslip.io
```

预期 HTTPS 返回 `200` 或跳转到 `/login`，响应包含 `server: Caddy`。

检查端口监听：

```bash
sudo ss -lntp | grep -E ':(80|443|3000|5432)\b'
```

3000 和 5432 必须只绑定 `127.0.0.1`。

## 9. 自动重新部署

代码更新后执行：

```bash
cd /opt/smart-chat
make redeploy
```

它会自动执行部署锁、环境检查、`git pull --ff-only`、PostgreSQL 备份、镜像构建、migration、Caddy/Web/Worker 重建和健康检查。详细说明见《自动重新部署指南》文档。

## 10. 查看日志

```bash
make logs
docker compose logs -f caddy
docker compose logs -f web
docker compose --profile worker logs -f worker
docker compose logs -f postgres
```

Caddy 证书申请成功日志包含：

```text
certificate obtained successfully
```

## 11. 数据备份

```bash
make backup
```

Compose 命名卷：

| 卷 | 数据 |
|---|---|
| `smart-chat-postgres` | 数据库 |
| `smart-chat-artifacts` | 图片和大结果 |
| `smart-chat-caddy-data` | TLS 证书和 ACME 状态 |
| `smart-chat-caddy-config` | Caddy 运行配置 |

禁止在生产环境执行 `docker compose down -v`，该命令会删除命名卷。

## 12. 停止和重启

停止容器但保留数据：

```bash
make stop
```

重新启动完整服务：

```bash
docker compose --profile worker up -d postgres web worker caddy
```

修改 `.env` 后使用 `--force-recreate` 让容器读取新环境变量：

```bash
docker compose --profile worker up -d --force-recreate web worker caddy
```

## 13. Self-hosted Runtime

默认 `AGENT_RUNTIME_MODE=legacy` 只需要传统 Worker。配置真实 `SELF_HOSTED_RUNTIME_EXECUTOR` 后，才可启动：

```bash
docker compose --profile self-hosted-runtime up -d runtime-worker
```

Runtime executor 必须存在于容器内，宿主机路径不能在没有挂载的情况下直接使用。

## 14. 上线验收

- [ ] `postgres` 为 healthy，`web`、`worker`、`caddy` 为 running。
- [ ] HTTP 自动跳转 HTTPS，证书受浏览器信任。
- [ ] 3000、3011、5432 没有暴露到公网。
- [ ] 用户能登录、创建房间和发送消息。
- [ ] Agent Worker 无 401，Agent 能返回消息。
- [ ] 重启 Docker 或服务器后服务自动恢复。
- [ ] PostgreSQL 和 Artifact 已配置异机备份。

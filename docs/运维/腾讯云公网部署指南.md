# Smart Chat 腾讯云公网部署指南

## 1. 适用范围

本文用于将 Smart Chat 部署到一台腾讯云 CVM，并提供公网 HTTPS 访问。假设代码已经拉取到服务器，部署采用：

```text
公网用户 -> Caddy :443 -> Next.js :3000
                              |
                              +-> PostgreSQL :5432
                              +-> Agent Worker
                              +-> 外部 AI Provider
```

当前没有自有域名时，建议临时使用 `sslip.io` 根据公网 IP 生成域名并申请可信证书。正式生产应购买并使用自己控制的域名。

## 2. 服务器与安全组

推荐起步配置：4 vCPU、8 GB 内存、80 GB SSD、Ubuntu 22.04/24.04。

腾讯云安全组只开放：

| 端口 | 来源 | 用途 |
|---|---|---|
| 22 | 管理员固定 IP | SSH |
| 80 | `0.0.0.0/0` | 证书验证和 HTTPS 跳转 |
| 443 | `0.0.0.0/0` | HTTPS |

不要向公网开放 `3000`、`3011`、`5432`。这些端口只能由本机或私有网络访问。

## 3. 安装运行环境

```bash
sudo apt update
sudo apt install -y ca-certificates curl git
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
```

重新登录 SSH 后检查 Docker：

```bash

```

项目已经在 Node.js 22 完整验证。Node.js 24 满足当前 Next.js 和 Prisma 的版本要求，但部署前必须运行全量检查。以下使用 Node.js 22：

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node --version
npm --version
```

## 4. 生成生产密钥

运行：

```bash
openssl rand -base64 48
openssl rand -hex 32
openssl rand -base64 48
openssl rand -base64 36
```

四个结果分别用于 `SESSION_SECRET`、`AI_CONFIG_ENCRYPTION_KEY`、`AGENT_WORKER_SECRET` 和数据库密码。每个值必须独立生成，不能复用。

### 4.1 SESSION_SECRET

用于签名和校验登录 Session。攻击者获得该值后可能伪造用户身份，因此必须至少 32 字符、只保存在服务器 Secret/环境变量中。

轮换该值会使现有登录会话全部失效，用户需要重新登录。这通常是可接受的应急操作。

### 4.2 AI_CONFIG_ENCRYPTION_KEY

用于 AES-256-GCM 加密数据库中的 AI Provider/API Key。即使数据库泄露，攻击者也不能只凭密文获得 Provider 密钥。

这个密钥不能随意更换或丢失。丢失后，数据库里已经保存的 Provider 密钥无法恢复；更换前必须先用旧密钥解密并重新加密，或者在管理台重新录入所有 Provider 密钥。

代码在未配置该值时会回退到 `SESSION_SECRET`，但生产环境必须单独配置，使会话签名密钥轮换不会破坏 AI 凭据。

### 4.3 AGENT_WORKER_SECRET

用于认证 Worker 对 `/api/internal/agent-worker` 的内部调用，防止公网用户伪造 Worker 请求触发后台任务扫描。

Web 和 Worker 必须配置同一个值。它不能出现在浏览器代码、日志或公开仓库中。

### 4.4 数据库密码

用于 PostgreSQL 用户认证。项目 Compose 中的默认密码只适合本地开发，公网服务器必须替换。数据库端口仍应绑定 `127.0.0.1`，密码不能代替网络隔离。

### 4.5 密钥保存要求

- `.env` 权限设为 `600`。
- 不提交 `.env` 到 Git。
- 在密码管理器或 Secret Manager 中做加密备份。
- 不把密钥直接写入 systemd unit 或命令历史。

## 5. 配置环境变量

进入项目并创建配置：

```bash
cd /opt/smart-chat
cp .env.example .env
chmod 600 .env
```

生产配置示例：

```env
DATABASE_URL="postgresql://smart_chat:替换为数据库密码@127.0.0.1:5432/smart_chat?schema=public"

SESSION_SECRET="替换为第一个随机值"
AI_CONFIG_ENCRYPTION_KEY="替换为第二个随机值"
AGENT_WORKER_SECRET="替换为第三个随机值"

COOKIE_SECURE=true
AGENT_WORKER_URL="http://127.0.0.1:3000/api/internal/agent-worker"

ARTIFACT_STORAGE_BACKEND=local
ARTIFACT_STORAGE_DIR="/var/lib/smart-chat/artifacts"
ARTIFACT_RETENTION_DAYS=30

AI_PROVIDER_HOST_ALLOWLIST="api.openai.com,generativelanguage.googleapis.com"
AGENT_RUNTIME_MODE=legacy
```

这些生产值的原因：

| 变量 | 原因 |
|---|---|
| `DATABASE_URL` 使用 `127.0.0.1` | 数据库不经过公网；若 Web 在容器内，应改用 Compose 服务名 `postgres` |
| `COOKIE_SECURE=true` | Session Cookie 只通过 HTTPS 发送，避免在明文 HTTP 中泄露 |
| `AGENT_WORKER_URL` 使用回环地址 | Worker 调用内部 API 不绕公网和反向代理 |
| `ARTIFACT_STORAGE_DIR` 使用固定绝对路径 | `.data` 或容器临时目录可能在重新部署时丢失 |
| `AI_PROVIDER_HOST_ALLOWLIST` 明确列举域名 | 防止管理员配置被用于 SSRF 访问内网地址 |
| `AGENT_RUNTIME_MODE=legacy` | 当前传统 Worker 可以直接工作；Self-hosted Runtime 仍需配置真实 executor |

如果新增 AI Provider，必须把它的准确主机名加入 allowlist。不要使用 `*`。

## 6. 配置 PostgreSQL

先修改 `compose.yaml`：

```yaml
services:
  postgres:
    environment:
      POSTGRES_DB: smart_chat
      POSTGRES_USER: smart_chat
      POSTGRES_PASSWORD: 替换为与DATABASE_URL一致的密码
    ports:
      - "127.0.0.1:5432:5432"
```

然后启动：

```bash
docker compose up -d postgres
docker compose ps
```

注意：PostgreSQL 只在首次创建数据卷时读取 `POSTGRES_PASSWORD`。如果已经用旧密码初始化过卷，单纯修改 Compose 不会修改数据库密码，需要执行 `ALTER ROLE` 或在确认没有重要数据后重建数据卷。

## 7. 构建和初始化数据库

```bash
npm ci
npx prisma generate
npx prisma migrate deploy
npm run lint
npm run typecheck
npm test
npm run build
```

只有需要演示账号和演示数据时才运行：

```bash

```

Seed 完成后立即修改默认账号密码。生产环境不要使用 `prisma db push` 代替已审核的 migration。

创建 Artifact 目录：

```bash
sudo mkdir -p /var/lib/smart-chat/artifacts
sudo chown -R "$USER":"$USER" /var/lib/smart-chat
chmod 700 /var/lib/smart-chat/artifacts
```

## 8. 使用 systemd 运行 Web

创建 `/etc/systemd/system/smart-chat-web.service`：

```ini
[Unit]
Description=Smart Chat Web
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/smart-chat
Environment=NODE_ENV=production
Environment=PORT=3000
Environment=HOSTNAME=127.0.0.1
EnvironmentFile=/opt/smart-chat/.env
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

将 `User`、`WorkingDirectory` 和 `EnvironmentFile` 改成服务器实际值。

## 9. 使用 systemd 运行 Worker

创建 `/etc/systemd/system/smart-chat-worker.service`：

```ini
[Unit]
Description=Smart Chat Agent Worker
After=network.target smart-chat-web.service
Requires=smart-chat-web.service

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/smart-chat
Environment=NODE_ENV=production
EnvironmentFile=/opt/smart-chat/.env
ExecStart=/usr/bin/npm run worker
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

加载并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now smart-chat-web smart-chat-worker
sudo systemctl status smart-chat-web --no-pager
sudo systemctl status smart-chat-worker --no-pager
curl -I http://127.0.0.1:3000
```

不要在尚未配置 `SELF_HOSTED_RUNTIME_EXECUTOR` 时启动 `runtime-worker`。

## 10. 无自有域名时启用 HTTPS

假设公网 IP 为 `43.123.45.67`，临时域名使用：

```text
43-123-45-67.sslip.io
```

验证解析：

```bash
getent hosts 43-123-45-67.sslip.io
```

安装 Caddy：

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl gpg
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/gpg.key \
  | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt \
  | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install -y caddy
```

配置 `/etc/caddy/Caddyfile`：

```caddy
43-123-45-67.sslip.io {
    encode zstd gzip
    reverse_proxy 127.0.0.1:3000

    header {
        Strict-Transport-Security "max-age=31536000"
        X-Content-Type-Options "nosniff"
        Referrer-Policy "strict-origin-when-cross-origin"
    }
}
```

验证并启动：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl enable --now caddy
sudo systemctl reload caddy
curl -I https://43-123-45-67.sslip.io
```

如果证书申请失败，检查安全组、防火墙、80/443 端口和域名解析。`sslip.io` 是第三方临时域名，不适合正式品牌和长期生产；购买域名后只需把 Caddyfile 站点地址改为自己的域名，并设置 DNS A 记录。

直接对公网 IP 使用自签名证书虽然能加密连接，但浏览器会显示不受信任警告，不适合普通用户访问。

## 11. 上线检查

```bash
docker compose ps
systemctl --no-pager status smart-chat-web smart-chat-worker caddy
sudo ss -lntp
journalctl -u smart-chat-web -n 100 --no-pager
journalctl -u smart-chat-worker -n 100 --no-pager
journalctl -u caddy -n 100 --no-pager
```

确认：

- 公网只能访问 80/443。
- `3000` 和 `5432` 只监听 `127.0.0.1`。
- HTTPS 证书有效且 HTTP 自动跳转 HTTPS。
- 登录 Cookie 带 `Secure`、`HttpOnly`、`SameSite`。
- Worker 能调用内部 API，没有 401。
- 重启服务器后 Web、Worker、PostgreSQL、Caddy 自动恢复。
- 数据库和 `/var/lib/smart-chat/artifacts` 有独立备份。

## 12. 更新与回滚

部署新版本：

```bash
cd /opt/smart-chat
git pull --ff-only
npm ci
npx prisma generate
npx prisma migrate deploy
npm run build
sudo systemctl restart smart-chat-web smart-chat-worker
```

更新前备份数据库。数据库 migration 必须保持向后兼容；如果应用回滚但 migration 不可逆，不能只执行 `git checkout`。应用日志和数据库迁移状态应共同作为发布证据。
